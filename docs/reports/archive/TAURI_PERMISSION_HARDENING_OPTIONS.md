# TAURI_PERMISSION_HARDENING_OPTIONS

本文件对离线专业版 Tauri 权限收窄做三种方案对比。评估重点是安全性、用户体验、D 盘路径、中文路径、文件夹导入、输出目录选择和发布可行性。

## 方案 A：保守方案

保留当前权限，只补充安全说明和发布说明。

| 维度 | 结论 |
| --- | --- |
| 安全性 | 权限偏宽，`fs.all`、`dialog.all`、`C:/**`、`D:/**` 审核观感较弱 |
| 用户体验 | 最稳定，几乎不影响用户选择任意本地路径 |
| 是否支持 D 盘 | 支持 |
| 是否支持中文路径 | 支持 |
| 是否支持文件夹导入 | 支持 |
| 是否支持输出目录选择 | 支持 |
| 是否适合离线专业版 | 可用，但正式发布可信度一般 |
| 推荐程度 | 低。只适合临时过渡或测试阶段 |

优点：功能回归风险最低。  
缺点：权限过宽，不利于隐私友好和商业发布说明。

## 方案 B：半收窄方案

关闭全量开关，保留显式必要权限；保留用户目录、桌面、文档、下载、图片、视频、音频；移除 `C:/**`；暂时保留 `D:/**`。

| 维度 | 结论 |
| --- | --- |
| 安全性 | 明显好于当前配置，去掉 C 盘全盘范围和全量文件系统开关 |
| 用户体验 | 大多数用户目录场景不受影响，D 盘仍可用 |
| 是否支持 D 盘 | 支持 |
| 是否支持中文路径 | 支持，需真实 Tauri 窗口回归 |
| 是否支持文件夹导入 | 支持，需真实 Tauri 窗口回归 |
| 是否支持输出目录选择 | 支持，需真实 Tauri 窗口回归 |
| 是否适合离线专业版 | 适合当前发布前阶段 |
| 推荐程度 | 高。本轮建议优先尝试 |

优点：降低发布权限风险，同时保留用户明确需要的 D 盘和批量输出能力。  
缺点：如果用户选择 C 盘非用户目录作为输入或输出目录，可能受限，需要在发布说明中提示优先使用用户目录或 D 盘工作目录。

## 方案 C：严格方案

移除 `C:/**` 和 `D:/**`，只允许系统用户目录、桌面、文档、下载、图片、视频、音频。

| 维度 | 结论 |
| --- | --- |
| 安全性 | 最强 |
| 用户体验 | 风险最高，可能破坏用户 D 盘项目、外接盘和自定义输出目录 |
| 是否支持 D 盘 | 不支持或需要动态授权验证 |
| 是否支持中文路径 | 用户目录内支持，D 盘中文路径可能失败 |
| 是否支持文件夹导入 | 用户目录内支持，任意目录不保证 |
| 是否支持输出目录选择 | 用户目录内支持，任意目录不保证 |
| 是否适合离线专业版 | 当前不适合 |
| 推荐程度 | 低。建议作为 Tauri v2 动态授权专项或应用商店审核专项再做 |

优点：权限最小化最彻底。  
缺点：很可能破坏离线专业版最核心的“任意本地目录批量处理”体验。

## 推荐方案

本轮推荐方案 B：半收窄方案。

执行边界：

1. 移除 `C:/**`。
2. 暂时保留 `D:/**`。
3. `dialog.all=false`，保留具体 dialog 子权限。
4. `fs.all=false`，保留读取、扫描、写入、存在性检查、创建目录。
5. 当前代码未使用 `fs.copyFile`，改为关闭。
6. 不动 `path.all`。
7. 不动 `shell.open`。
8. 不动 WebView2 `offlineInstaller`。
9. 不打开 `process` 和 `updater`。
10. 修改后重新执行测试、构建、打包和重点冒烟。
