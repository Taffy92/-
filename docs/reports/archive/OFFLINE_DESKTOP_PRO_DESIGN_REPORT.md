# 离线专业版页面重构设计审查报告

日期：2026-05-27

## 结论先说

当前离线安装版的问题，不是“颜色不够深”或者“按钮不够多”，而是**页面骨架仍然像网页工具页**：

1. 结构还保留了网页式三栏卡片感。
2. 工具分类不够像桌面软件的模块导航。
3. 预览、任务、参数、日志之间的主次关系不够明确。
4. 空间利用偏松，缺少国企 / 办公 / 政府内网工具常见的“紧凑、稳定、低干扰”气质。

这次我先不给代码，只给你 5 套可选设计图方向。你选定后，我再按你选中的方案做大范围重构。

## 必须保留的边界

- 不新增登录 / 注册 / 会员 / API / 社交 / 云同步能力。
- 不改 LOGO 图标。
- 不改功能逻辑、权限、隐私、本地处理原则。
- 说明文档、许可证、隐私说明继续保留。
- 不重新部署到 CloudBase。

## 你要求的分类结构

离线专业版的导航必须明确分成：

- 图片工具：裁剪、加水印、压缩
- 文档工具：PDF、Word、Excel
- 音视频工具：视频格式转换、视频提取音频、音频格式转换
- 批量处理：离线队列、输出目录、失败重试、日志、历史

## 设计原则

1. 看起来像桌面软件，不像网页。
2. 先操作，再解释。
3. 分类比营销文案更重要。
4. 预览区必须是主角，不是附属块。
5. 参数区要像“属性面板”，不是网页表单。
6. 任务区要像“队列”，不是普通列表。
7. 少装饰，少大圆角，少大留白，少宣传句。

## 方案 1：三栏工作台

### 结构

- 左：模块分类导航
- 中：预览区 + 任务区 + 结果区
- 右：参数面板 + 任务信息 + 日志入口

### 设计图

```text
+----------------------------------------------------------------------------------+
| 品牌区 | 状态条 | 输出目录 | 开始 | 停止 | 清空完成 | 当前任务状态               |
+--------------------+--------------------------------------+-------------------------+
| 图片工具           | 预览区                               | 参数面板                |
| 文档工具           |--------------------------------------| 输出设置                |
| 音视频工具         | 任务队列 / 处理进度 / 结果管理       | 任务信息                |
| 批量处理           |                                      | 日志 / 历史             |
|                    | 结果列表                             |                         |
+--------------------+--------------------------------------+-------------------------+
```

### 特点

- 这是最像真正桌面工作台的方案。
- 适合高频切换功能。
- 预览区可以直接放在任务区上方，操作链路短。

### 优点

- 认知最稳。
- 最符合国企 / 办公 / 政府内网工具的使用习惯。
- 以后扩展批量能力最方便。

### 风险

- 信息密度高，必须控制字号、间距和层级。
- 如果右侧参数太多，会显得重。

### 适用结论

**推荐度：最高。** 这是最适合你当前产品定位的主方案。

## 方案 2：顶部命令栏 + 中央焦点区

### 结构

- 顶部：应用标题 + 快速操作命令栏
- 左：分类导航
- 中：大预览区 + 任务区
- 右：参数与状态

### 设计图

```text
+----------------------------------------------------------------------------------+
| 品牌区 | 图片工具 | 文档工具 | 音视频工具 | 批量处理 | 开始 | 停止 | 输出目录    |
+--------------------+--------------------------------------+-------------------------+
| 左侧分类导航        | 预览区 / 当前文件                     | 参数与状态              |
|                    | 任务队列                              |                         |
|                    | 结果 / 日志                           |                         |
+--------------------+--------------------------------------+-------------------------+
```

### 特点

- 视觉上更干净。
- 操作按钮都集中在顶部，像“命令条”。

### 优点

- 入口清楚。
- 适合强调“开始 / 停止 / 输出目录”这类高频操作。

### 风险

- 如果顶部内容过多，会重新回到网页感。
- 对大屏更友好，小窗口需要压缩按钮数量。

### 适用结论

**推荐度：第二。** 适合你想要“更现代，但不花哨”的方向。

## 方案 3：左树形分类 + 中央双层区

### 结构

- 左：树形分类导航
- 中上：预览区
- 中下：任务队列 + 结果管理
- 右：参数抽屉

### 设计图

```text
+----------------------+--------------------------------------+----------------------+
| 图片工具             | 预览区                               | 参数抽屉             |
|  ├ 裁剪              |--------------------------------------| 输出格式             |
|  ├ 加水印            | 任务队列                             | 输出目录             |
|  └ 压缩              | 结果管理                             | 批量选项             |
| 文档工具             |                                      | 日志 / 历史          |
| 音视频工具           |                                      |                      |
| 批量处理             |                                      |                      |
+----------------------+--------------------------------------+----------------------+
```

### 特点

- 更接近“企业软件系统”的感觉。
- 分类更细时，这种结构最稳。

### 优点

- 分类层级最清晰。
- 适合后续继续增加子功能。

### 风险

- 需要更强的视觉克制，不然会像后台管理系统。
- 桌面软件感强，但可能略显冷。

### 适用结论

**推荐度：第三。** 如果你想要更强的系统感，它很合适。

## 方案 4：仪表盘式工作区

### 结构

- 顶部：状态总览
- 中央：当前工具卡 + 预览卡 + 任务卡
- 右侧：参数卡组
- 底部：历史与日志

### 设计图

```text
+----------------------------------------------------------------------------------+
| 状态总览：任务数 / 成功 / 失败 / 当前模块 / 输出目录                           |
+----------------------+------------------------------+---------------------------+
| 模块导航             | 当前工具卡                   | 参数卡组                  |
| 图片 / 文档 / 音视频 | 预览卡                       | 输出 / 批量 / 日志        |
| 批量处理             | 任务卡                       |                           |
+----------------------+------------------------------+---------------------------+
| 历史记录 / 日志 / 失败重试 / 输出路径                                          |
+----------------------------------------------------------------------------------+
```

### 特点

- 比前三种更有“操作台”味道。
- 适合一眼看到状态，再进入操作。

### 优点

- 运行态信息清楚。
- 适合领导检查、办公复用、长时间挂着处理。

### 风险

- 如果卡片太多，会回到网页式 dashboard。
- 需要非常克制卡片边框和圆角。

### 适用结论

**推荐度：第四。** 偏展示，但可用性不错。

## 方案 5：任务先行型

### 结构

- 左：分类导航
- 中：任务列表为主，预览作为上方窄条
- 右：折叠式参数面板
- 底部：状态栏

### 设计图

```text
+----------------------+--------------------------------------+----------------------+
| 分类导航             | 预览条                               | 参数面板             |
| 图片 / 文档 / 音视频 |--------------------------------------| 输出设置             |
| 批量处理             | 任务列表                             | 批量设置             |
|                      | 结果 / 失败原因                      | 日志 / 历史          |
+----------------------+--------------------------------------+----------------------+
| 底部状态栏：离线可用 / 当前任务 / 成功 / 失败 / 输出目录                         |
+----------------------------------------------------------------------------------+
```

### 特点

- 更偏批处理软件。
- 任务量大时最好用。

### 优点

- 最像“生产工具”。
- 对批量处理场景特别友好。

### 风险

- 对单文件用户不够直观。
- 预览存在感偏弱。

### 适用结论

**推荐度：第五。** 如果你更强调批量，不强调单文件体验，可以选它。

## 我的建议排序

1. **方案 1：三栏工作台**
2. **方案 2：顶部命令栏 + 中央焦点区**
3. **方案 3：左树形分类 + 中央双层区**
4. **方案 4：仪表盘式工作区**
5. **方案 5：任务先行型**

## 为什么我最推荐方案 1

- 最贴近“国企、办公、政府内网工具”的稳定感。
- 最容易把“分类、预览、队列、参数”分清楚。
- 最适合你现在这个产品的真实定位。
- 后续大范围改造时，风险最低。

## 这次我不会碰的东西

- 不动业务逻辑。
- 不动权限。
- 不动隐私承诺。
- 不动广告位。
- 不动下载授权流程。
- 不动文档、许可证、隐私说明。

## 你审查时重点看什么

请你重点判断这 4 件事：

1. 哪一套最不像网页。
2. 哪一套最像办公软件。
3. 哪一套最适合高频切换图片 / 文档 / 音视频 / 批量。
4. 哪一套最适合后续做大范围重构。
