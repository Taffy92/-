# 在线方案 C：编辑式流程页

## 定位与信息架构

- 定位：把复杂参数整理成可阅读、可核对的编辑式流程，适合 PDF / Word / Excel 多页工具。
- 首页：编辑式主标题 → 三步任务说明 → 本地处理承诺，减少工具卡片堆叠。
- 工具页：当前工具条 → 01 选择文件 → 02 输出方式与页码 → 03 预览与开始。
- 桌面右侧只放本地处理说明、帮助与广告位，不再复制参数。
- 无永久工具侧栏；切换工具始终是顶部显式动作。

## 统一目录规范

- 顶部“切换工具”打开图片工具、PDF 工具、文档工具、音视频工具、OCR 工具五列目录。
- 首页五个入口、当前工具面包屑和移动端切换器使用完全一致的分类名称。
- 编辑式三步只组织当前任务，不成为另一套功能分类。
- “离线批量”只标记当前工具的批量或目录输出范围；离线版仍作为独立产品入口保留。

## 字体与排版

- 功能界面：`Microsoft YaHei UI`, `Segoe UI`, system-ui。
- 仅首页展示标题可用 `Georgia`, `Songti SC`, serif；不从网络加载字体。
- 字阶：12 / 14 / 16 / 22 / 34 / 52px。
- 行高：正文 1.65，步骤标题 1.3，展示标题 1.08。
- 字重：正文 400、控件 600；通过字号和留白建立层级，不依赖全粗体。

## 尺寸与组件

- 间距：4 / 8 / 16 / 24 / 32 / 48 / 72px。
- 圆角：2 / 4 / 6px；以细分隔线而非卡片阴影组织结构。
- 控件高度：40px；移动端 44px。
- 阴影：仅对话框 `0 20px 52px rgba(37,37,37,.22)`。
- 主按钮：橙红实底；次按钮：白底细边；步骤编号只作导航，不伪装按钮。
- 表单：标签位于字段上方；单选、范围、滑杆组成同一参数网格。
- 图标：项目现有 `lucide-react`，16px，1.5px 描边；正文步骤不以图标替代文字。

## 状态语言

- 空闲：第三步保持简洁摘要，不制造空白大卡。
- 已选择：第一页缩略图、页数、大小和处理位置集中在第一步。
- 处理中：第三步原位切换为进度与当前页；取消入口始终可见。
- 成功：结果名、内存保留说明、下载结果。
- 失败：第三步内联错误；文件和参数仍保留，便于修正后重试。
- 多页结果：在线原型允许下载 ZIP；离线实现仍必须写入同名子文件夹。

## 响应式与动效

- `≥1181px`：主流程 + 320px 说明栏。
- `821–1180px`：说明栏移至流程末尾，参数保持两列。
- `≤820px`：顶部只保留品牌与“工具”按钮；三步单列；工具面板沿用五分类且不出现侧栏。
- `390px`：步骤标题、文件摘要、参数、状态严格顺序排列；无横向滚动。
- 动效：反馈 120ms、步骤内容 180ms、对话框 240ms；`cubic-bezier(.25,.75,.2,1)`。
- 不做滚动劫持和章节自动跳转；降低动态模式下即时切换。

## 实现风险

- 难度：中。需要重新组织信息层级，但组件本身简单。
- 风险：过多留白会降低高频用户效率；复杂工具需验证参数是否能稳定归入三个步骤。
