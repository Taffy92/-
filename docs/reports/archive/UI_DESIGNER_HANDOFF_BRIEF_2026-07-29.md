# 万能格式转换器 UI 全面重设计任务书

文档日期：2026-07-29  
当前正式版本：v1.1.0  
本次设计对应版本：暂定 v2.0.0  
文档用途：提供给专业 UI 设计师，用于完成在线版与 Windows 离线版的全套界面设计及可点击 HTML 原型  
项目名称：万能格式转换器

---

## 1. 本次委托目标

我们希望对“万能格式转换器”的在线版与 Windows 离线版进行一次完整的 UI 和交互重设计。

这不是只换颜色、圆角和首页横幅，而是允许设计师重新思考页面结构、内容层级、操作流程、预览区域、状态反馈和动效语言。现有 HTML 原型只用于说明功能范围和交互状态，不要求照搬其布局或视觉表现。

最终希望达到以下结果：

- 在线版具有鲜明、成熟、专业的前端设计质感，首页可以更具视觉表现力和品牌记忆点。
- 离线版像一款可靠的 Windows 专业生产力软件，信息清楚、操作直接、长时间使用不疲劳。
- 两端共享品牌基因，但不强行使用同一种布局。
- 所有真实功能、处理状态、错误反馈、广告边界、隐私原则和离线规则都能在设计稿中完整体现。
- 最终交付在线版和离线版两份完整、可点击、可独立打开的 HTML 原型，供后续技术可行性审阅。

## 2. 产品简介

万能格式转换器是一款以“文件在当前设备处理”为核心原则的文件处理工具，分为：

- 在线版：浏览器内本地处理，适合单文件或少量文件的快速操作。
- Windows 离线专业版：支持断网使用、大文件、批量任务、本地目录输出和离线授权。

产品覆盖四类主要能力：

- 图片处理
- PDF、Word、Excel 文档处理
- 音频与视频处理
- 图片与 PDF 的本地 OCR 文字识别

用户文件、预览内容、OCR 结果和转换结果不得发送给广告平台或其他第三方服务。

## 3. 产品定位与目标用户

### 3.1 产品定位

这是一款强调隐私、本地处理和实用效率的综合文件工具，不是云盘、在线办公套件或账号型 SaaS。

### 3.2 主要用户

- 临时需要转换、压缩或整理文件的普通用户。
- 处理报名材料、证件照片、扫描件和办公附件的个人用户。
- 需要把 PDF、Word、Excel 转为图片进行预览或分享的办公用户。
- 需要批量处理图片、文档、音视频的大文件用户。
- 处理敏感资料或处于断网环境的离线版用户。
- 需要从图片或 PDF 中识别文字并导出 TXT 或 Word 的用户。

### 3.3 用户最关心的问题

- 文件会不会上传。
- 当前工具是否支持自己的格式。
- 参数应该怎么选。
- 处理进行到哪里。
- 失败原因是什么。
- 结果保存到了哪里。
- 在线版与离线版有什么区别。

界面应优先回答这些问题，不应让装饰抢占操作注意力。

## 4. 技术背景与设计落地条件

设计师不需要编写正式产品代码，但设计方案应考虑以下现实条件：

- 在线版使用 Next.js 15、React 18 和 Tailwind CSS。
- Windows 离线版使用 Tauri。
- 在线版和离线版复用同一套图片、文档、音视频、OCR 处理核心。
- 项目已具备 GSAP，可以实现页面进入、模块过渡和微交互动效。
- 正式产品需要适配中文界面。
- 在线版需要响应桌面、平板和手机尺寸。
- 离线版主要运行于 Windows 10/11 x64，重点设计桌面窗口。
- 离线版需要在断网状态下完整显示，不依赖 CDN 字体、远程图标、在线图片或广告资源。

## 5. 不可改变的产品边界

以下内容属于硬性约束，设计方案不得改变：

### 5.1 品牌与隐私

- 保留现有产品名称和 Logo，不重新设计或替换 Logo。
- 文件始终在当前设备处理。
- 不设计“上传云端”“云端转换”“云端历史记录”等入口。
- 不展示可能让用户误认为文件已上传的云朵进度、服务器队列等表达。
- 页面公共资源请求与用户文件处理必须在文案和视觉上明确区分。

### 5.2 账号与支付

- 不增加登录、注册、会员中心和用户等级。
- 不增加在线支付购买功能。
- 微信和支付宝二维码只用于自愿赞赏。
- 赞赏不与授权、下载、功能解锁或售后权益关联。
- 不设计扫码后自动授权或半自动授权流程。

### 5.3 广告

- 在线版只保留百度联盟广告接口。
- 不出现 Google、Google AdSense 或相关视觉、文案和占位。
- 离线版完全不显示广告，不加载广告网络资源。
- 广告不得靠近文件选择、开始处理、保存、下载和错误重试按钮。

### 5.4 功能边界

- 不设计视频或图片“去除水印”功能。
- 现有“添加水印”功能继续保留。
- 不增加与现有图片、文档、音视频和 OCR 工作流无关的功能。
- 私有离线授权后台不属于此次公开 UI 设计范围。

## 6. 设计总方向

### 6.1 两端共享的品牌基因

在线版和离线版建议共享：

- Logo 使用方式。
- 一套主色和状态色逻辑。
- 字体层级与数字格式。
- 图标风格。
- 按钮、输入框、开关、进度条和错误提示的基础语言。
- 对“本地处理”“不上传”“断网可用”的统一表达。

### 6.2 在线版设计气质

关键词：

- 精致
- 现代
- 有记忆点
- 专业前端作品感
- 清楚而不普通
- 有动效但不炫技

首页可以大胆使用版式、留白、文字节奏、SVG 或 DOM 动画建立识别度；进入工具工作区后应明显收敛，让操作效率成为主角。

### 6.3 离线版设计气质

关键词：

- 专业
- 简洁
- 高效
- 稳定
- 信息明确
- 长时间使用舒适

离线版不需要复制在线首页的视觉表现，应更接近成熟桌面生产力软件。用户打开软件后，应能迅速完成：

选择工具 → 添加文件 → 调整参数 → 开始处理 → 查看状态 → 找到结果

### 6.4 需要避免的“AI 味”

- 避免大面积紫蓝渐变、发光边框、玻璃拟态和无意义粒子。
- 避免所有模块都使用相同圆角卡片和悬浮阴影。
- 避免虚构数据、虚构用户评价和伪技术参数。
- 避免大量无意义英文缩写或“未来矩阵”“智能引擎舱”等空泛文案。
- 避免用图标代替所有文字，使用户无法快速理解按钮作用。
- 避免为了视觉冲击牺牲文件名、状态、参数和错误信息的可读性。
- 避免在工具页面加入持续运行、抢占 CPU 或显卡资源的背景动画。

设计师可以自由选择深色、浅色或混合主题，但必须保证工具操作区具有足够的对比度和清晰层级。

## 7. 在线版完整设计范围

在线版需要覆盖以下公开页面和状态。

### 7.1 全局框架

需要设计：

- 顶部导航
- 移动端菜单
- 全局页脚
- 页面切换和当前导航状态
- 全局提示 Toast
- 通用确认弹窗
- 通用错误弹窗
- 赞赏弹窗
- 备案、隐私、条款、许可证、更新日志等合规入口

建议主导航至少包含：

- 首页
- 在线工具
- 增强工具
- 使用教程
- 下载离线版
- 关于

导航不宜过度拥挤，次要入口可以归入菜单或页脚。

### 7.2 在线首页

首页是在线版最重要的品牌页面，可以发挥设计师的审美和动效能力，但必须以真实产品为核心。

建议包含：

1. 首屏品牌区
   - 一句简短、有力度的主标题。
   - 明确表达文件在当前设备处理、不经过云端转换。
   - 主要按钮进入在线工具。
   - 次要按钮进入离线版下载。
   - 可使用轻量 SVG、Canvas 之外的 DOM 动画或格式流转演示。

2. 功能总览
   - 图片
   - 文档
   - 音视频
   - OCR
   - 每一类展示真实功能和适用场景。

3. 本地处理说明
   - 选择本地文件
   - 当前设备处理
   - 当前设备生成结果
   - 下载或保存到本机

4. 在线版与离线版区别
   - 在线版轻量、方便、适合单文件或少量文件。
   - 离线版适合断网、大文件和批量任务。

5. 教程与常见场景
   - 展示真实教程入口。
   - 不使用空泛营销内容。

6. 百度联盟广告位
   - 必须在已有实质内容之后。
   - 只标注“广告”。
   - 未接入正式广告时，生产环境应能完全隐藏。

7. 页脚
   - 关于、联系、隐私、条款、教程、下载、许可证、更新日志。
   - 赞赏支持使用低干扰入口。

首页不要直接铺满两张二维码，也不要在首屏放广告。

### 7.3 在线工具页

在线工具页需要让用户迅速理解“当前工具、文件、参数、状态、结果”。

设计师可以重新布局，但必须完整容纳：

- 工具分类与切换。
- 当前工具标题与简短说明。
- 文件选择和拖放区域。
- 文件名称、格式、尺寸、大小等摘要。
- 文件预览。
- 当前工具参数。
- 开始处理、取消、重新处理。
- 处理进度。
- 成功结果与下载。
- 错误原因与解决建议。
- 浏览器能力或文件大小限制提示。
- “文件仅在本机处理”的持续可见提示。

推荐设计桌面端的工作区结构：

- 左侧或顶部：工具导航。
- 中央：文件和预览。
- 右侧或抽屉：参数。
- 底部或结果区：状态、结果和下载。

这只是推荐，不限制设计师提出更好的方案。

移动端不能简单把三栏按比例缩小，建议转换成顺序式流程：

工具 → 文件 → 参数 → 处理 → 结果

在线工具操作区不放广告。

### 7.4 在线基础工具清单

以下功能已存在，设计时不能遗漏：

#### 图片

- 图片裁切
- 像素或百分比调整
- 添加文字水印
- 添加图片水印
- 图片压缩

#### 文档

- PDF 转图片
- Word 转图片
- Excel 转图片

#### 音视频

- 视频格式转换
- 音频格式转换
- 视频提取音频

### 7.5 在线增强工具清单

增强工具可以设计为独立页面，也可以在不造成工具导航混乱的前提下并入统一工作台。

#### 图片增强

- 图片格式转换
- 旋转与翻转
- EXIF 查看与清理

#### PDF

- 图片合成 PDF
- PDF 合并
- PDF 拆分与页面提取
- PDF 页面重新排序、删除和旋转
- PDF 文字或图片水印
- PDF 页码、页眉和页脚

#### 音视频增强

- 音视频裁剪
- 视频静音
- 视频截图
- 视频转 GIF
- 音频裁剪
- 多段音频顺序拼接
- 音量调整
- 淡入淡出

#### OCR

- 图片文字识别
- PDF 文字识别
- 中文、英文和中英混合识别
- 导出 TXT
- 导出可编辑 Word
- 导出视觉版式优先的图片型 Word

OCR 导出选项需要清楚说明：

- 可编辑 Word 会重建文字和段落，复杂表格、公式、多栏内容不保证完全保持原稿格式。
- 图片型 Word 更接近原页面视觉，但正文主要以页面图像呈现，不等同于完全可编辑文档。

### 7.6 在线工具状态

每个代表性工具至少需要设计以下状态：

| 状态 | 必须表达的内容 |
| --- | --- |
| 空状态 | 支持格式、文件限制、选择或拖放入口 |
| 已载入 | 文件摘要、预览、移除、更换、参数 |
| 参数不完整 | 哪个参数缺失、如何修正 |
| 处理中 | 当前步骤、进度、取消、文件未上传提示 |
| 完成 | 输出文件名、大小、预览、下载、再次处理 |
| 部分完成 | 多项任务中成功与失败数量 |
| 错误 | 原因、可操作建议、重新尝试 |
| 浏览器不支持 | 兼容性说明和离线版建议 |
| 文件过大 | 明确限制、降低参数或使用离线版 |
| 内存不足 | 解释原因并提供可执行建议 |

### 7.7 教程和内容页面

教程页面既服务用户，也关系到百度收录和广告审核，不应设计成只有标题的空卡片。

当前内容包括：

- 图片裁切
- 图片尺寸调整
- 图片加水印
- 图片压缩
- PDF 转图片
- Word 转图片
- Excel 转图片
- 视频格式转换
- 音频格式转换
- 视频提取音频
- 在线版与离线版区别
- 如何确认文件没有上传
- 不同使用场景的参数建议

需要设计：

- 教程目录或筛选。
- 正文阅读页或展开式详情。
- 适合截图、步骤和注意事项的内容结构。
- 上一篇、下一篇或相关教程。
- 教程中后段或文章结束处的百度广告位。

广告必须与正文按钮、下载按钮和工具入口保持明显距离。

### 7.8 离线版下载页

需要设计：

- 离线版主要优势。
- 当前版本、大小、发布日期和 SHA256。
- EXE 与 MSI 两种安装包。
- 直接下载 3 天试用版。
- Windows 10/11 x64 支持说明。
- 断网使用、大文件和批量处理说明。
- 安装、SmartScreen 和校验提示。
- 发布说明、隐私、许可证、第三方组件、FFmpeg 说明入口。
- 在线版与离线版的清晰对比。

下载页不投放广告，避免广告与下载按钮混淆。

### 7.9 其他公开页面

需要建立统一的正文与合规页面模板，覆盖：

- 关于我们
- 联系我们
- 隐私政策
- 使用条款
- 开源许可证与第三方组件声明
- 更新日志
- 发布说明与安装文档

这些页面不需要复杂动画，但需要良好的阅读宽度、标题层级、目录、代码或校验值展示以及移动端适配。

更新日志页面只展示：

- 版本号
- 更新日期
- 原有功能
- 新增功能

不展示开发过程、测试命令、部署步骤或内部操作记录。

### 7.10 在线赞赏入口

需要设计一个低干扰的“赞赏支持”入口和弹窗：

- 微信二维码
- 支付宝二维码
- 桌面端可并排，移动端上下排列。
- 二维码不得被裁切、拉伸或覆盖。
- 不修改二维码矩阵和定位区。
- 不显示收款人姓名。

建议文案：

> 如果这个工具帮你节省了时间，可以自愿赞赏支持后续维护。赞赏完全自愿，不影响任何功能，不代表购买、授权或服务承诺。

必须补充：

- 二维码不用于自动授权。
- 不记录用户是否扫码或付款。
- 弹窗可通过关闭按钮、Esc 和遮罩关闭。

## 8. 百度联盟广告设计要求

### 8.1 首期只设计两个广告位置

- 首页内容广告：功能和隐私说明之后。
- 教程内容广告：完整内容的中后段或结束处。

### 8.2 不允许的位置

- 首页首屏。
- 在线工具工作区。
- 文件上传区域。
- 开始处理、下载结果和错误重试按钮附近。
- 离线版下载按钮附近。
- 弹窗、浮层和 Toast。
- 错误页、空状态或内容不足的页面。
- Windows 离线版的任何位置。

### 8.3 广告容器表现

- 清楚标注“广告”。
- 与产品推荐、下载和功能卡片有明确视觉区别。
- 不使用箭头、闪烁、假按钮或诱导点击文案。
- 预留响应式尺寸，避免广告加载造成明显页面跳动。
- 设计“无广告代码时不显示”的页面效果，不能留下大块空框。
- 不展示任何 Google 广告样例。

## 9. Windows 离线版完整设计范围

### 9.1 应用整体框架

离线版需要设计为独立桌面应用，而不是把网站页面装进窗口。

建议覆盖：

- 窗口标题栏或与系统标题栏协调的顶部区域。
- 顶部命令栏。
- 左侧工具导航。
- 开始页。
- 文件任务工作台。
- 右侧参数区或可替代的参数交互。
- 底部状态栏。
- 设置与关于。
- 赞赏弹窗。
- 试用与离线授权界面。

### 9.2 离线开始页

开始页建议承担：

- 常用工具快捷入口。
- 最近任务或本地记录入口。
- 本地模式已就绪提示。
- 输出目录入口。
- 简短的新手引导。
- 当前试用或授权状态。

不需要在线首页式的大型宣传首屏。

### 9.3 离线专业工作台

必须清楚表达：

- 当前工具。
- 已选择的文件数量。
- 添加文件和添加文件夹。
- 输出目录。
- 多文件平铺预览。
- 单个文件的格式、大小和处理状态。
- 当前工具参数。
- 批量开始、暂停或取消。
- 成功、失败、等待、暂停数量。
- 打开输出目录。
- 重试失败项和清空列表。

设计师可以重新布局预览区域，但不能把多文件隐藏在只有一行文件名的列表里。

### 9.4 离线文件预览硬性规则

用户一次选择多个文件时，必须平铺显示每个文件：

- 图片显示缩略图。
- PDF 显示第一页缩略图。
- Word 显示第一页缩略图。
- Excel 显示第一页缩略图。
- 视频显示首帧容器。
- 音频可以显示音频类型、时长或简洁波形占位。

每个文件卡片或条目至少包含：

- 文件名。
- 文件类型。
- 文件大小或页数、时长。
- 当前状态。
- 错误说明。
- 移除或重试入口。

需要考虑长文件名、多页文件、大批量任务和单项失败。

### 9.5 离线输出规则

设计中需要正确表达以下规则：

- 批量结果写入独立输出文件夹。
- 多页 PDF、Word、Excel 的逐页结果写入同名子文件夹。
- 不回退为 ZIP 或 7Z 汇总包。
- 完成后提供“打开输出目录”。
- 每个任务应能看出结果保存位置或相对目录。

### 9.6 离线功能范围

离线版包含在线基础工具和增强工具，并额外强调：

- 多文件批量队列。
- 添加文件夹。
- 大文件处理。
- 本地输出目录。
- 断网使用。
- 离线 FFmpeg 能力。
- 批量图片尺寸调整。
- 批量加水印。
- 批量图片压缩。
- 批量 PDF、Word、Excel 转图片。
- 批量视频转换。
- 批量音频转换。
- 批量视频提取音频。

### 9.7 离线状态

需要设计：

- 首次打开。
- 无任务。
- 文件已载入。
- 等待队列。
- 正在处理。
- 暂停或取消。
- 全部完成。
- 部分完成。
- 单项失败。
- 文件不支持。
- 输出目录不可写。
- 磁盘空间不足。
- 本地组件不可用。
- 关闭软件时仍有任务的确认弹窗。

### 9.8 离线试用与授权

离线专业版首次运行自动开启本机 3 天试用，试用结束后通过离线授权码或 `license.mrx` 授权文件继续使用。

设计需要覆盖：

- 试用中及剩余天数。
- 试用即将结束。
- 试用已结束。
- 授权已激活。
- 授权已过期。
- 授权文件无效。
- 授权码错误。
- 系统时间异常。
- 机器码展示和复制。
- 导出授权申请文件。
- 输入授权码。
- 导入 `license.mrx`。
- 激活处理中。
- 激活成功与失败。

不得设计登录、会员账户或联网验证界面。授权界面只控制离线版使用权，不接触用户处理文件。

### 9.9 离线设置、关于和赞赏

设置可以包含：

- 默认输出目录。
- 处理完成后是否打开目录。
- 是否清理图片或媒体元数据。
- 动效开关或减少动态效果。
- 最近任务记录说明。
- 当前版本。
- 隐私、许可证和第三方组件入口。

赞赏入口放在“支持作者”或“关于”区域，不长期占用主工作区。

离线赞赏弹窗：

- 使用安装包内的本地微信和支付宝 PNG。
- 断网也能显示。
- 不加载支付 SDK。
- 不加载广告。
- 不记录扫码和付款。
- 不与授权功能关联。

## 10. 动效要求

### 10.1 在线版

可以使用较有表现力的动效：

- 首屏标题和说明分层进入。
- 格式转换流程的节点或连线动画。
- 功能模块进入视口时的轻微位移和透明度变化。
- 页面切换和弹窗过渡。
- 文件拖入、读取、处理和完成状态动画。
- 按钮、选项和格式切换的微交互。

建议：

- 页面进入动效约 450 至 700ms。
- 按钮和控件反馈约 120 至 220ms。
- 悬停位移控制在 2 至 4px。
- 动效应支持 `prefers-reduced-motion`。
- 文件处理时暂停非必要背景动画。

### 10.2 离线版

离线版动效只服务反馈：

- 导航切换。
- 参数展开和收起。
- 文件加入队列。
- 任务状态变化。
- 进度和完成反馈。
- 弹窗进入和退出。

建议控制在 120 至 220ms，不使用视差、粒子、持续呼吸背景或大型首页动画。

## 11. 响应式与窗口适配

### 11.1 在线版

至少设计并验证：

- 1440 × 900
- 1280 × 720
- 768 × 1024
- 390 × 844

要求：

- 无横向溢出。
- 导航在小屏幕下有完整替代方案。
- 工具参数不遮挡预览和主要按钮。
- 二维码在手机上完整显示。
- 长文件名可换行或省略，并可查看完整名称。
- 弹窗在小屏幕下可滚动。

### 11.2 离线版

建议重点设计：

- 1440 × 900
- 1280 × 720
- 1024 × 720 的紧凑窗口

要求：

- 不依赖页面整体无限向下滚动完成主要任务。
- 核心操作在常见窗口尺寸下可见。
- 左侧导航、中央任务区和参数区在空间不足时有合理折叠方案。
- 文件平铺区域可以独立滚动。
- 弹窗不能超出窗口。

## 12. 无障碍与可用性

设计中需要体现：

- 正常、悬停、按下、禁用和键盘焦点状态。
- 文本与背景的基本对比度。
- 错误不能只用红色区分，需要图标或文字。
- 成功、警告、错误和处理中状态具有一致规则。
- 所有纯图标按钮提供文字提示或 Tooltip。
- 弹窗有明确标题、关闭和返回路径。
- 重要操作提供确认，但不对普通操作过度确认。
- 不让用户在处理中误以为页面卡死。
- 用户关闭动画后不损失功能。

## 13. 文案原则

- 使用自然、直接、专业的中文。
- 功能名优先使用用户熟悉的叫法。
- 参数旁提供短而有效的解释。
- 错误文案说明“发生了什么、为什么、下一步怎么办”。
- 不使用夸张的“极速、革命性、无限、百分百无损”等无法保证的表述。
- 不虚构支持格式数量、性能提升或用户数量。

推荐统一隐私提示：

> 文件仅在当前设备处理，不上传服务器。

推荐统一赞赏提示：

> 赞赏完全自愿，不影响任何功能，不代表购买、授权或服务承诺。

## 18. 给设计师的简短结论

这次设计可以大胆重做，但不是自由添加产品功能。

在线版需要像一个专业前端设计师认真打磨的公开产品，有品牌、有节奏、有细节，同时保持工具区域清楚可靠；离线版需要像一款成熟的 Windows 生产力软件，让用户少思考、少跳转、少出错。

请优先解决真实文件处理场景，而不是只完成一张漂亮首页。我们希望最终看到的是两套完整、可操作、能够进入开发阶段的产品界面。
