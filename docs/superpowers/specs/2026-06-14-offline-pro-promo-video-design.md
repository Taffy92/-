# 万能格式转换器离线专业版宣传视频设计

日期：2026-06-14

## 背景

本项目需要一条宣传视频，同时露出在线网站和 Windows 离线专业版，但主推对象是离线专业版。在线版只作为低门槛入口和可信补充，离线专业版承担主要转化目标。

已确认方向：

- 产物：一条宣传视频，不新增宣传网站页面。
- 比例：16:9 横屏母版，同时保持竖屏裁切安全区。
- 时长：约 40-50 秒，目标 48 秒。
- 声音：中文旁白、同屏字幕、背景音乐都必须包含。
- 视觉：产品 Pro 矩阵。黑底、克制、蓝色与青绿色点亮，贴合现有官网气质。
- 叙事：场景痛点 → 在线版入口 → 离线专业版展开 → 隐私原则 → 双 CTA。

## 目标

1. 让观众在前 6 秒理解常见办公格式问题。
2. 明确在线版可用于临时单文件处理。
3. 把 Windows 离线专业版作为主角，重点展示批量、大文件、敏感文件、断网办公、本地输出。
4. 明确隐私原则：文件尽量在本机处理，不上传服务器，不调用云端转换 API。
5. 片尾引导访问 `gszhmrx.cn`，并下载 Windows 离线专业版试用。

## 非目标

- 不新增登录、会员、云端转换或上传能力。
- 不修改在线站、桌面端业务代码或产品功能。
- 不使用未经确认授权的商业音乐、图片、视频素材。
- 不承诺项目文案中没有明确支持的功能或格式数量。
- 不把安装包或授权私钥等敏感发布资产放进视频项目。

## 成功标准

- 视频源码是独立 HyperFrames 项目，建议目录为 `docs/marketing/hyperframes/offline-pro-promo/`。
- 主合成为约 48 秒，16:9 横屏，核心文字、字幕、LOGO、CTA 位于竖屏安全区。
- 离线专业版占主要篇幅，约 60% 时长。
- 包含中文旁白、同步字幕和背景音乐。
- 背景音乐使用原创生成的轻电子循环，音量低于旁白，避免版权不清。
- 通过 HyperFrames 的 `lint`、`validate`、`inspect` 检查；如果本机 Node 版本不满足 HyperFrames 要求，要在交付说明中明确。
- 能提供本地预览 URL；环境支持时渲染 `offline-pro-promo.mp4`。

## 视觉身份

色板：

- 背景黑：`#000000`
- 面板黑：`#111112`
- 输入/深灰：`#1c1c1e`
- 主文字：`#f5f5f7`
- 次级文字：`#a1a1a6`
- 品牌蓝：`#2997ff`
- 安全青绿：`#30d5c8`

字体：

- 使用系统无衬线字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei", "PingFang SC", sans-serif`
- 字幕与数据标签使用足够字号，确保横屏和竖屏裁切后可读。

风格约束：

- 保持克制、可信、产品化，不做夸张大字报风格。
- 使用局部发光、线框矩阵、文件卡片和真实界面感作为视觉主线。
- 不使用大面积深色线性渐变，降低视频压缩后色带风险。
- 不把在线版做成主角，在线界面只短暂露出。

## 分镜与文案

### 00-06 秒：办公格式痛点

画面：文件类型卡片快速堆叠，显示图片、PDF、视频、音频等卡住场景。

旁白：图片太大传不上去，PDF 想转图片，视频格式打不开，只想从视频里提取音频。

字幕：日常办公的格式问题，不该卡住你。

### 06-12 秒：在线版快速入口

画面：`gszhmrx.cn` 与在线工具台短暂展开，强调临时处理。

旁白：临时处理，可以直接打开万能格式转换器在线版。

字幕：在线版：打开网站，快速处理单个文件。

### 12-21 秒：离线专业版登场

画面：Windows 离线专业版工作台从黑底矩阵中展开，镜头推近。

旁白：但如果是公司资料、客户文件、大文件，或者一批文件要处理，更适合 Windows 离线专业版。

字幕：主推：Windows 离线专业版。

### 21-31 秒：批量导入与本地工作台

画面：左侧功能导航、中间平铺预览、右侧参数和任务状态依次点亮。多文件卡片进入队列。

旁白：安装后直接进入本地工作台，选择工具，批量导入，图片、PDF、Word、Excel、音频和视频都能排进任务。

字幕：批量导入 · 平铺预览 · 本地处理。

### 31-39 秒：独立输出文件夹

画面：任务进度完成，输出文件夹展开；PDF/Word/Excel 多页结果进入同名子文件夹。

旁白：结果保存到独立文件夹，多页文档按同名子文件夹输出，不用再把结果压成一个包。

字幕：独立结果文件夹，多页文档清楚归档。

### 39-48 秒：隐私原则与双 CTA

画面：本地处理盾牌线框、站点域名、下载离线专业版按钮和 LOGO 同屏。

旁白：文件尽量在本机处理，不上传服务器，不调用云端转换 API。访问 gszhmrx.cn，也可以下载离线专业版试用。

字幕：gszhmrx.cn · 下载 Windows 离线专业版。

## 音频方案

旁白：

- 使用 HyperFrames TTS 生成中文旁白。
- 旁白语速保持平稳，避免压缩信息。
- 字幕不依赖旁白才可理解，静音播放也成立。

背景音乐：

- 必须包含。
- 使用项目内生成的原创轻电子背景循环，例如低频脉冲、柔和合成器 pad、轻微节拍。
- 音乐文件建议由本地脚本生成为 WAV，避免第三方版权风险。
- 旁白期间音乐音量压低，片尾 CTA 可略微抬升但不盖过语音。

## 技术方案

目录建议：

```text
docs/marketing/hyperframes/offline-pro-promo/
├── DESIGN.md
├── index.html
├── script.md
├── assets/
│   ├── bgm.wav
│   └── voiceover.wav
└── renders/
```

实现要点：

- `DESIGN.md` 固化视觉身份和反模式。
- `index.html` 使用 HyperFrames 顶层 composition，注册 GSAP timeline。
- 每个场景有入口动画，并使用转场衔接，避免跳切。
- 不使用无限循环动画；背景微动使用有限 repeat。
- 使用 muted video 与独立 audio 轨道的 HyperFrames 媒体规范。
- 所有动态元素从最终布局反推动画，先确保 hero frame 不溢出。

## 验证

实现完成后运行：

```powershell
npx hyperframes lint
npx hyperframes validate
npx hyperframes inspect
```

如环境支持，继续运行：

```powershell
npx hyperframes preview --port 3017
npx hyperframes render --output renders/offline-pro-promo.mp4 --quality standard
```

如果 HyperFrames 要求 Node 22，而当前项目正式构建要求 Node 20，则视频项目验证可临时使用 Node 22；不改变仓库根目录 `.nvmrc`、`package.json` 的 Node 20 发布要求。

## 风险与处理

- Node 版本冲突：视频项目验证和产品构建分开处理，不修改主项目版本约束。
- TTS 中文效果不理想：保留 `script.md`，必要时改为人工录音替换 `voiceover.wav`。
- 背景音乐压过旁白：通过音量和均衡控制，优先保证旁白清晰。
- 界面细节不够真实：先用产品化重绘界面表达能力，必要时再补真实截图，但不接触用户文件或敏感资产。
