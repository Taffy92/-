# 万能格式转换器全新界面、百度广告与赞赏入口升级可行性报告

报告日期：2026-07-28  
当前版本：v1.1.0  
建议目标版本：v2.0.0  
结论：可行，建议实施

## 一、执行结论

本次升级可以在不重写图片、文档、音视频与 OCR 处理核心的前提下完成。现有项目已经具备 Next.js 在线版、Tauri 离线版、共享功能包、Web/Desktop 运行模式分流、GSAP 动效能力、百度联盟验证信息和本地静态资源体系，适合进行一次完整的界面系统重构。

建议将本次升级定义为 v2.0.0，而不是普通的小版本更新，原因如下：

- 在线版首页、工具页、教程页、下载页及公共页面将采用全新的视觉系统和信息架构。
- 离线版将重做为独立的专业工作台，不再简单沿用在线版布局。
- 在线广告体系将完全移除 Google，只保留百度联盟接入口。
- 在线版和离线版都会增加微信、支付宝自愿赞赏入口。
- 动效、响应式、无障碍、性能和广告合规将作为同一套设计系统重新验收。

百度联盟是否最终批准仍取决于百度的审核结果。界面重做可以显著改善体验、内容组织和页面完整性，但不能替代原创内容积累、百度收录和真实访问量。

## 二、已确认的项目基础

### 2.1 技术基础

- 在线版使用 Next.js 15、React 18 和 Tailwind CSS。
- 离线版使用 Tauri，并复用在线项目的静态构建产物。
- 图片、PDF、Word、Excel、音视频和 OCR 能力位于共享功能包中，界面可以重做而不改变核心处理方式。
- 项目已经使用 GSAP，可直接承担首屏、页面切换、模块进入和微交互动效。
- `NEXT_PUBLIC_APP_MODE` 已经将 Web 与 Desktop 模式分开。
- 离线版 CSP 当前只允许本地资源，具备继续保持无广告、无联网依赖的基础。

### 2.2 广告现状

当前项目仍包含以下 Google 广告残留：

- Google AdSense 组件和类型。
- Google 广告环境变量与默认发布商编号。
- `ads.txt` 中的 Google 记录。
- CSP 中的 `googlesyndication.com`、`doubleclick.net` 和 Google 连接白名单。
- 隐私政策、使用条款和网络测试中的 Google 描述。
- 广告配置当前默认提供商仍为 Google。

同时，项目已经存在百度联盟验证信息和百度广告组件雏形，因此可以在移除 Google 后收敛为单一百度广告实现。

### 2.3 赞赏资源现状

项目中已存在：

- `apps/web/public/donate/wechat-reward-qr.png`
- `apps/web/public/donate/alipay-reward-qr.png`

两张图片的收款姓名已经从二维码外部展示区域移除，二维码主体未被改写。正式发布前仍必须分别使用微信和支付宝真机扫码，完成小额测试，确认收款对象和支付功能正常。

支付宝二维码中心使用动漫人物，微信二维码中心使用个人照片。两者不影响扫码结构，但会降低整体品牌统一度，也可能带来个人信息或第三方角色版权方面的顾虑。更稳妥的长期方案是在微信、支付宝中使用自有 Logo 或中性头像重新生成二维码；在此之前可以先使用现有二维码，但不能修改二维码矩阵和定位区域。

## 三、本次升级范围

### 3.1 必须完成

- 推翻并重做在线版全部公开界面。
- 推翻并重做离线版主要工作界面。
- 在线版保留合规广告位，只支持百度联盟。
- 完全删除 Google 广告代码、配置、域名白名单、文案和 `ads.txt` 记录。
- 在线版增加微信、支付宝赞赏入口。
- 离线版增加微信、支付宝赞赏入口，不包含广告组件和广告网络请求。
- 保留文件本地处理、不上传服务器、不调用云端转换 API 的原则。
- 保留在线版与离线版现有功能，不因界面重做减少功能。
- 同步更新版本号和更新日志。

### 3.2 明确不做

- 不增加登录、注册、会员系统。
- 不恢复个人收款码自动授权或半自动授权。
- 不把赞赏付款与功能解锁、授权码、授权文件或下载资格关联。
- 不给离线版接入广告、统计 SDK 或远程广告资源。
- 不上传用户文件、预览、转换结果、OCR 内容、Canvas、Blob 或 ArrayBuffer。
- 不为了视觉效果引入重型 3D 引擎或持续占用显卡的 WebGL 场景。

## 四、总体设计策略

在线版与离线版应共享品牌基因、字体比例、图标语言和基础色彩，但不应强行使用同一套页面布局。

| 项目 | 在线版 | 离线版 |
| --- | --- | --- |
| 核心感受 | 精致、鲜明、具有记忆点 | 专业、安静、可靠 |
| 主要目标 | 建立品牌、引导工具使用、承载内容与广告 | 提高任务效率、降低学习成本 |
| 页面密度 | 中等，允许大面积留白和展示性模块 | 较高，以文件、参数和任务状态为中心 |
| 动效强度 | 中等，重点用于首页与页面切换 | 低，仅保留状态反馈和必要过渡 |
| 广告 | 仅百度联盟，限定位置 | 完全没有 |
| 赞赏 | 页脚入口和独立弹窗/页面 | 设置或关于区域入口，使用本地图片 |

设计上应避免常见的“AI 味”：

- 不堆叠大面积紫蓝渐变、玻璃卡片、发光边框和无意义粒子。
- 不在中文产品中大量使用生硬英文标签、伪技术术语和“未来矩阵”等装饰文案。
- 不让所有卡片拥有相同圆角、阴影、渐变和悬浮动画。
- 不用过多图标替代清晰文字，不牺牲可读性换取视觉效果。
- 所有文案应围绕真实功能和用户任务，而不是空泛宣传。

## 五、在线版界面方案

### 5.1 推荐视觉方向

推荐采用“数字工具出版物”风格：

- 主色使用深石墨、暖白和高纯度青蓝，少量使用橙色作为状态强调。
- 标题使用有力度的中文无衬线字体，正文保持高可读性。
- 采用清晰网格、精确分割线、错位排版和少量大字号数字，形成专业前端作品感。
- 卡片不依赖重阴影，以边界、层级、留白和状态变化建立质感。
- 首页可以更有表现力，工具工作区必须主动收敛。

### 5.2 首页结构

1. 顶部导航
   - 产品 Logo
   - 在线工具
   - 功能分类
   - 使用教程
   - 下载离线版
   - 关于与赞赏

2. 首屏品牌区
   - 一句清晰主标题，突出“本地处理”和“文件不上传”。
   - 一个主要按钮进入在线工具，一个次要按钮下载离线版。
   - 右侧使用轻量 SVG/DOM 动态演示格式从输入到输出的过程。
   - 不在首屏放广告、二维码或复杂参数。

3. 功能目录
   - 图片、文档、音视频、OCR 四个分类。
   - 展示真实功能名称、适用场景和支持格式。
   - 点击后直接进入对应工具状态，不增加无意义的中间跳转。

4. 隐私与能力证明
   - 用简洁流程解释“选择文件—本地处理—本地保存”。
   - 清楚区分页面资源请求与用户文件上传。

5. 教程与场景内容
   - 展示独立教程和常见使用场景。
   - 为百度收录提供真正可阅读、可持续更新的内容页面。

6. 合规百度广告位
   - 放在已有实质内容之后。
   - 与按钮、工具操作和下载入口保持明显距离。

7. 页脚
   - 备案、隐私、条款、许可证、更新日志、联系信息。
   - 增加“赞赏支持”入口，但不直接在页脚铺开两张大二维码。

### 5.3 在线工具页

建议采用三段式工作流，但不照搬离线工作台：

- 左侧或顶部：功能分类与搜索。
- 中央：文件导入、预览和处理状态。
- 右侧或抽屉：当前功能参数。
- 底部：结果列表、保存和重新处理。

移动端改为“功能选择—文件—参数—结果”的纵向步骤，不把桌面三栏强行缩小。

工具操作区域不投放广告，原因是上传、转换、下载按钮密集，容易产生误点，也不符合百度联盟对广告和点击区域保持距离的要求。

### 5.4 动效方案

优先复用现有 GSAP，不新增重型动画依赖：

- 首屏标题、说明、按钮采用 450～700ms 的分层进入。
- 功能卡片进入视口时使用轻微位移和透明度变化。
- 格式流程图使用 SVG 描边、节点流动或遮罩动画。
- 页面切换只做短距离过渡，不制造等待感。
- 按钮和卡片悬停位移控制在 2～4px。
- 上传、转换和完成状态使用明确、可中断的状态动画。
- 支持 `prefers-reduced-motion`，用户关闭动画后仍可正常操作。
- 文件处理进行时暂停非必要背景动画，避免争抢 CPU 和显存。

## 六、离线版界面方案

### 6.1 推荐视觉方向

离线版采用“专业桌面生产力工具”风格：

- 默认使用中性深灰或浅灰工作区，避免过度霓虹和大面积装饰。
- 功能区、文件区、参数区边界明确。
- 信息密度比在线版高，但控件尺寸、间距和文字层级保持舒适。
- 强调当前工具、文件数量、任务状态、输出目录和剩余试用状态。

### 6.2 主界面布局

1. 顶部命令栏
   - 当前功能名称
   - 添加文件、添加文件夹
   - 输出目录
   - 开始处理
   - 设置、关于

2. 左侧工具导航
   - 图片工具
   - 文档工具
   - 音视频工具
   - OCR
   - 最近使用

3. 中央任务与预览区
   - 多文件必须平铺预览。
   - 图片显示缩略图。
   - PDF、Word、Excel 显示第一页缩略图。
   - 视频显示首帧容器。
   - 支持单项状态、错误提示、移除和重新处理。

4. 右侧参数区
   - 只显示当前工具相关参数。
   - 推荐值优先，高级参数折叠。
   - 参数名称使用用户能理解的中文。

5. 底部状态区
   - 任务进度、成功/失败数量。
   - 输出目录快捷入口。
   - 本地处理和无网络上传提示。

### 6.3 离线动效

- 导航切换、参数展开、任务状态变化使用 120～220ms 短过渡。
- 不使用首页式大动画、滚动视差、粒子或持续背景动画。
- 转换时只保留进度和必要状态反馈。
- 动画关闭后不影响任何功能。

### 6.4 离线赞赏入口

- 放在“关于/支持作者”区域，不长期占用工作区。
- 点击后弹出微信和支付宝两个二维码。
- 二维码使用安装包内的本地 PNG 资源，断网也能显示。
- 文案固定为“自愿赞赏，不影响任何功能，也不产生授权或售后权益”。
- 不记录用户是否扫码、是否付款，不引入支付 SDK。

## 七、百度联盟广告设计与合规方案

### 7.1 仅保留两个广告位置

建议首期只保留：

- 首页内容广告：位于功能目录和隐私说明之后。
- 教程内容广告：位于完整文章的中后段或文章结束处。

不建议在以下位置投放：

- 在线工具操作区。
- 文件上传、开始转换、保存和下载按钮附近。
- 转换结果区和完成提示区。
- 下载离线版页面。
- 弹窗、悬浮层、错误页、空白页和离线版。

### 7.2 广告容器要求

- 广告上方只标注“广告”，不使用“推荐”“支持本站请点击”等诱导文字。
- 广告外观必须与正文清楚区分。
- 周围不放箭头、下载图标或容易造成误触的装饰。
- 设置合理的响应式预留高度，减少页面跳动。
- 未配置百度正式广告代码时，生产环境完全隐藏空广告框。
- 只有在线 Web 构建允许加载百度脚本。
- 百度脚本不得接触文件对象、预览内容、OCR 文本或转换结果。

### 7.3 Google 完全移除范围

实施时应删除：

- `GoogleAdSlot` 组件及 Google provider 类型。
- 所有 `NEXT_PUBLIC_GOOGLE_AD_*` 环境变量。
- Google AdSense 发布商编号和默认广告位编号。
- `apps/web/public/ads.txt` 中的 Google 记录。
- CSP 中所有 Google、DoubleClick 和 Google Syndication 域名。
- 隐私政策、使用条款中的 Google AdSense 描述。
- 测试文件和网络白名单中的 Google 广告规则。
- 构建配置、部署环境和历史示例中的有效 Google 广告参数。

第三方许可证中名称含有 `google` 的开源依赖记录不属于广告代码，不应误删。

### 7.4 百度审核配套

界面重做同时需要：

- 为主要工具和教程建立独立、原创、可索引页面。
- 保证所有一级、二级页面都有完整内容。
- 修复死链，并确保 sitemap 只包含已上线页面。
- 在百度搜索资源平台提交 sitemap 和新增高质量链接。
- 持续更新内容并积累真实访问量后再申请。
- 不购买访问、不互点、不奖励用户浏览或点击广告。

## 八、赞赏入口设计与风险控制

### 8.1 在线版

- 导航或页脚设置低干扰“赞赏支持”入口。
- 点击后打开独立弹窗或轻量页面。
- 两个二维码并排展示，移动端改为上下排列。
- 明确标注微信、支付宝。
- 使用 `loading="lazy"`，避免二维码增加首页首屏负担。
- 二维码保持 PNG 无损格式，不进行有损压缩。

### 8.2 统一文案

建议固定使用：

> 如果这个工具帮你节省了时间，可以自愿赞赏支持后续维护。赞赏完全自愿，不影响任何功能，不代表购买、授权或服务承诺。

### 8.3 验收

- 微信真机扫码成功。
- 支付宝真机扫码成功。
- 小额支付确认收款对象正确。
- 姓名不在二维码外部界面中显示。
- 手机和桌面端均不裁切二维码定位区和静区。
- 离线安装包断网时仍能打开二维码。

## 十一、验收标准

### 11.1 视觉与交互

- 1440×900、1280×720、390×844 三种尺寸无布局溢出。
- 在线版有明确品牌感，但工具操作区保持清晰。
- 离线版首次使用者可以在不阅读说明书的情况下完成“选择功能—添加文件—设置参数—处理—找到结果”。
- 键盘焦点可见，主要操作支持键盘访问。
- 正文和控件满足基本对比度要求。
- 开启减少动态效果后，页面无功能损失。

### 11.2 性能

- 在线首页 LCP 目标不高于 2.5 秒。
- CLS 目标低于 0.1。
- 动画不长期占用主线程。
- 二维码和非首屏图片延迟加载。
- 文件处理时不运行非必要背景动画。

### 11.3 广告与隐私

- 项目源码、构建产物和网络请求中不存在 Google 广告代码及域名。
- 在线版未配置百度正式广告代码时不显示空广告框。
- 百度广告只出现在白名单位置。
- 广告与上传、转换、下载控件保持明显距离。
- 离线版不包含广告 DOM、广告脚本和广告网络请求。
- 用户文件和处理结果不传给百度或任何第三方。

### 11.4 功能与发布

- 现有图片、文档、音视频和 OCR 功能回归通过。
- 离线多文件平铺预览和独立文件夹输出规则保持不变。
- 微信、支付宝二维码在 Web 和离线安装包中扫码通过。
- `npm test`
- `npm run build:web`
- `npm run build:edgeone`
- `npm run check:privacy`
- `npm run check:network`
- `npm run package:desktop`

正式构建必须使用 Node 20 LTS 和 pnpm 9.15.4。

## 十二、主要风险与处理建议

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 百度联盟再次拒绝 | 广告暂时无法产生收入 | 先完成内容、收录和真实流量建设，广告位未获批时隐藏 |
| 全量 UI 重做影响现有功能 | 转换、预览或批量流程回归 | 保留核心处理模块，只替换外壳并逐功能回归 |
| 动画影响低性能设备 | 卡顿、转换变慢 | GSAP 仅用于必要区域，处理时暂停背景动画 |
| 二维码公开暴露个人头像 | 隐私与品牌不统一 | 长期使用自有 Logo 重新生成个人收款码 |
| 支付宝中心动漫形象 | 版权与专业感风险 | 建议重新生成中性头像版本，不修改现有二维码矩阵 |
| 在线与离线共用样式互相污染 | 两端视觉或功能异常 | 建立共享品牌变量与独立 Web/Desktop shell |
| 空广告占位影响百度审核 | 页面被认为空白或体验差 | 无正式广告代码时生产环境完全不渲染占位框 |

## 十三、最终建议

本次升级应按“先确认完整设计方向，再实现，再接百度广告”的顺序推进：

1. 先制作在线版和离线版完整可点击 HTML 原型，覆盖首页、工具页、弹窗、空状态、处理中、完成、错误和赞赏入口。
2. 审阅通过后，将原型拆分为正式组件，不改动核心转换逻辑。
3. 完成 Google 广告全量移除和百度单一接口收敛。
4. 完成赞赏入口和真机扫码验收。
5. 补齐独立功能页、教程页、百度收录与死链检查。
6. 统一升级到 v2.0.0，按既定简化格式填写更新日志。

从现有技术基础、资源和项目边界判断，该方案具备实施条件，风险可控，适合作为下一次正式大版本升级。
