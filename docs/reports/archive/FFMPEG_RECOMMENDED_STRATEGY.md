# FFMPEG_RECOMMENDED_STRATEGY

生成时间：2026-05-24

本文件记录“万能格式转换器”当前 FFmpeg / FFmpeg WASM 的推荐发布策略。本文件不是法律意见，正式商业发布前仍建议做法律和许可证复核。

## 产品策略

1. 在线版继续保留音频格式转换、视频格式转换、视频提取音频。
2. 在线版只支持轻量单文件或少量文件处理，不开放批量音视频处理。
3. 在线版继续使用本地 FFmpeg WASM：`/ffmpeg/ffmpeg-core.js`、`/ffmpeg/ffmpeg-core.wasm`。
4. 在线版不上传用户音频、视频或转换结果，不调用云转换 API。
5. 在线版增加“批量处理”入口，但只用于说明和引导下载 Windows 离线专业版。
6. 离线专业版继续保留完整批量处理能力，包括图片、Word、Excel、音频、视频批量处理。
7. 长期商业方案不是移除在线版音视频，而是为离线专业版专项评估 sidecar FFmpeg / LGPL FFmpeg 构建。

## 短期发布推荐

短期采用“保留在线版音视频 + 批量能力门控 + 补齐许可证说明”的方案：

1. 不删除在线版 FFmpeg WASM。
2. 不破坏在线版音频转换、视频转换、视频提取音频。
3. 在线版明确提示批量处理属于离线专业版。
4. 离线专业版保留批量任务队列、输出目录、失败重试、处理日志和任务历史。
5. `THIRD_PARTY_NOTICES.md`、`FFMPEG_LICENSE_NOTICE.md`、`OPEN_SOURCE_LICENSES.md` 必须持续保留 FFmpeg / GPL 风险说明和源码获取方式。

## 中期优化方向

1. 为在线版增加更清晰的单文件大小、时长和内存提示。
2. 保持在线版音视频处理轻量化，不进入批量任务队列。
3. 在下载页和批量入口中突出离线专业版的批量处理能力。
4. 对 FFmpeg WASM 的加载、缓存、错误提示和断网表现做专项验证。

## 长期合规最优方向

1. 为离线专业版设计 sidecar FFmpeg 方案。
2. 优先评估可证明来源的 LGPL FFmpeg 构建。
3. 如果继续使用 GPL 构建，则按 GPL 要求保留许可证、版权声明和源码获取方式。
4. 记录 FFmpeg 构建参数、版本号、SHA256、源码链接和许可证文本。
5. 对 sidecar 命令参数做白名单限制，避免任意命令执行风险。

## 是否建议在线版保留音视频转换

建议保留。

原因：

1. 在线版音视频是用户可感知的核心转换能力。
2. 当前实现仍在浏览器本地处理，不上传用户文件。
3. 在线版不开放批量音视频处理，性能和内存风险可通过文件大小提示控制。
4. 只要继续分发 FFmpeg WASM，就必须保留 FFmpeg / GPL 许可证说明和源码获取方式。

## 是否建议离线专业版保留音视频转换

建议保留，并继续保留批量处理能力。

原因：

1. 音视频批量转换更适合离线专业版。
2. 大文件、敏感文件和断网场景是专业版核心价值。
3. 批量任务队列、失败重试、输出目录和任务历史已形成专业版能力边界。

## 发布前必须确认

1. 在线版音视频转换没有外部 FFmpeg 请求。
2. 在线版音视频转换不上传文件或结果。
3. 离线专业版批量音视频处理断网可用。
4. FFmpeg / GPL 许可证说明可在网站和软件内查看。
5. 正式商业发布前完成法律/许可证复核。
