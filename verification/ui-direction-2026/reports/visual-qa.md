# 视觉与响应式 QA

## 覆盖范围

- 在线：3 个方向 × 首页 1440、工具页 1440、平板 768、手机 390 已选择 / 错误 / 成功、支持作者对话框、桌面完整目录、手机工具切换器，共 27 张。
- 离线：3 个方向 × 1280×820 空闲、1280×820 运行、1120×720 紧凑、1280×820 高级设置、本地授权、任务类型切换，共 18 张。
- 额外基线：当前在线首页、工具桌面、工具 390、当前离线 1280 / 1120、Word 第一页预览。

## 自动检查

- 所有原型页面监听 `console.error` 与 `pageerror`。
- 在线 1440 / 768 / 390 检查 `scrollWidth <= clientWidth`。
- 离线 1280×820 / 1120×720 同时检查无水平溢出和无整窗垂直溢出。
- 原型使用固定视口截图，不以全页截图掩盖首屏问题。
- 390px 三方向均不渲染桌面永久侧栏。
- 1120×720 三方向均维持命令、文件、参数与总状态可见。
- 完整目录固定为图片、PDF、文档、音视频、OCR 五类，顺序一致。
- 每套目录均检查 24 个功能、24 个唯一名称，重复数为 0。
- 自动抽取 `ToolsClient.webTabs` 与 `LocalToolsClient.tools` 后和原型目录比对：代码 24 / 原型 24，`missing = []`，`extra = []`。
- 用户界面禁用名称检查为 0 命中。
- 离线界面在线 Header 数为 0、广告容器数为 0。

最终 Playwright 全量结果：`45 cases / 0 issues`。检查项包含控制台错误、页面异常、水平溢出、离线整窗垂直溢出、移动工作区宽度、桌面侧栏隐藏、无名称按钮、缺失图片替代文本、无标签表单字段、五分类顺序、功能去重、离线广告边界、对话框语义和工具切换路由。

Playwright CLI 另外完成在线 A 目录语义快照及关闭交互；快照确认顶部导航、五分类、24 个功能和适用范围标签均可被辅助技术读取。

截图尺寸复核：45 张正式方案截图全部与命名视口一致，`0 dimension issues`。

## 人工视觉检查

- 对照图逐套检查方向锚点与原型的布局、配色、密度、边框、圆角、留白与状态。
- 文件名、文件大小、页数、时长、进度和输出目录使用真实长度样本。
- 图片、Word、Excel 和视频预览不是占位灰盒。
- 支持作者对话框保留自愿说明和原二维码静区。
- 失败状态显示原因与恢复动作；成功状态显示结果名与下一步。
- 离线高级设置在工作区原位展开，本地授权不引入登录或联网依赖。
- 两张跨方案信息架构对照图逐项检查首页、工作台、桌面目录和 390px 切换器。

## 可访问性检查

- 所有 HTML 使用 `lang="zh-CN"` 和响应式 viewport。
- 对话框使用 `role="dialog"`、`aria-modal="true"` 和标题关联。
- 运行状态使用 `aria-live`；错误状态使用 `role="alert"`。
- 图片提供与用途相符的替代文本。
- 图标方向要求复用现有 `lucide-react`，不以 emoji 传达状态。
- 移动端触控目标目标值为 44px；桌面键盘焦点必须有 2px 可见外环。
- 颜色状态同时配有文字，不仅依赖颜色。

## 运行环境与限制

- 当前机器为 Node 26.1.0，而项目正式发布基线要求 Node 20 LTS。
- 本轮只做视觉原型与截图，不执行正式构建或打包；正式实施前必须切回 Node 20。
- 产品设计插件中的 `design-qa` 技能当前不可用，本轮以方向锚点对照表、Playwright 视口检查、响应式检查与可访问性清单代替。
- 内置浏览器控制在本机初始化时出现 `Cannot redefine property: process`；本轮使用用户指定的 Playwright 和本机 Chrome 完成截图及 DOM 检查。

## 验收结论

原型层面满足本阶段信息架构修订验收：六套方向可独立比较，五分类和 24 个真实功能一致，在线 390px P0 有三种不同解法，离线最小窗口没有整窗滚动，关键状态和本地授权均有审查材料。正式页面尚未改动，因此这不是第三阶段实现完成声明。

项目既有校验也保持通过：

- `npm test`：25 个测试文件、134 个测试全部通过。
- `npm run check:privacy`：11 项全部通过。
- `npm run check:network`：4 项全部通过。

三项命令均提示当前 Node 26.1.0 不符合正式发布要求的 Node 20.x；这不影响本轮审查结论，但正式构建前必须切回 Node 20。
