# EdgeOne 私有离线授权后台设计

日期：2026-07-26

## 1. 背景

原 CloudBase 环境 `format-converter-prod-x-d71bce41` 已因停止续费而进入隔离状态。桌面端已经签发的离线授权不会因此失效，但原 `licenseAdmin` HTTP 后台无法继续承担随时随地生成授权码的职责。

项目网站和安装包下载已经迁移到 EdgeOne Pages。新的私有授权后台继续部署在同一 EdgeOne 站点，使用 EdgeOne Cloud Functions 完成登录、签名和历史查询，使用 EdgeOne Blob 保存加密后的授权记录。

后台入口固定为：

```text
https://gszhmrx.cn/admin/license/
```

该入口不出现在官网导航、站点地图或公开页面链接中，但不能把“隐藏地址”当作安全措施；实际访问权限由管理员密码和安全会话控制。

## 2. 目标

1. 管理员可以在国内网络下，使用手机或电脑随时打开后台。
2. 管理员输入客户提供的机器码后，可以生成与现有桌面端完全兼容的离线激活码和 `license.mrx`。
3. 结果页面突出一键复制、二维码和文件下载，不要求管理员或客户手工处理长授权码。
4. 每次签发和续期都保存一条不可覆盖的加密历史记录。
5. 续期保留客户尚未使用完的授权时间。
6. 私钥、管理员密码、客户资料、机器码和授权文件不得进入公开网页、安装包或 Git。
7. 保留本地授权生成器作为云端不可用时的应急工具。

## 3. 非目标

- 不为产品用户新增登录、注册、会员或在线授权账户。
- 不把文件转换、客户文件或转换结果上传到 EdgeOne。
- 不修改现有桌面端离线验证协议、公钥、试用规则和功能权限。
- 不向桌面端增加联网验证、吊销查询或激活回传。
- 不自动迁移本地 `license_records.json` 中的旧记录；新后台上线后的记录从零开始保存。旧授权仍按原有效期正常使用。
- 不开发多人管理员、角色权限、短信验证、TOTP 或密码找回。

## 4. 已确认的产品决策

### 4.1 部署方案

采用 EdgeOne Pages 静态管理页面、EdgeOne Cloud Functions 和 EdgeOne Blob 的组合。管理页面和接口使用同一域名，避免额外跨域配置。

未采用以下方案：

- Edge Functions + KV：运行环境和存储模型不如 Node.js Cloud Functions 适合复用现有 Ed25519 签名逻辑。
- GitHub Actions 手工签发：手机操作不便，国内网络可用性不足，并且不适合作为日常后台。
- 新建付费云服务器：会重新引入固定续费成本和服务器维护工作。

### 4.2 管理员认证

- 仅使用一个管理员密码。
- 密码可以是 6 位纯数字，不限制长度或复杂度。
- 页面不显示弱密码提示。
- 连续输错不锁定、不等待，也不设置应用层次数限制。
- 登录失败只返回统一的“密码不正确”，不暴露后台配置状态。
- 登录成功后创建 8 小时安全会话。

该选择意味着公开地址上的 6 位数字密码存在被穷举的风险。项目接受这一已知风险，不在实现时擅自加入密码复杂度或登录锁定规则。

### 4.3 历史与续期

- 保存私有授权历史。
- 每次签发都新增记录，不覆盖旧记录。
- 续期从该机器最近一条有效授权的到期时间继续累加。
- 计算公式为：

```text
续期起点 = max(当前时间, 该机器最近到期时间)
新到期时间 = 续期起点 + 续期天数
```

- 如果管理员从一条较旧记录点击“续期”，后端仍查找同一机器的最新记录，避免缩短有效期或重复从旧时间计算。
- 永久授权使用 `2099-12-31 23:59:59`（Asia/Shanghai）对应的 Unix 时间戳。

## 5. 总体架构

### 5.1 静态管理页面

`apps/web` 新增静态路由 `/admin/license/`。它只负责：

- 显示登录页、签发表单、生成结果和历史记录；
- 把密码发送给会话接口；
- 把机器码、客户名称、授权时长和备注发送给签发接口；
- 一键复制激活码、显示二维码、下载服务端返回的 `license.mrx`；
- 查询和筛选已授权记录。

浏览器不接收私钥、记录加密密钥或密码摘要，也不在 `localStorage`、`sessionStorage`、URL 或页面源码中保存管理员密码。

### 5.2 EdgeOne Cloud Functions

Cloud Functions 使用 Node.js 20，按职责拆分为以下接口：

| 路径 | 方法 | 作用 |
| --- | --- | --- |
| `/api/admin/license/health` | GET | 返回简单可用状态，不暴露配置细节 |
| `/api/admin/license/session` | POST | 校验管理员密码并创建 8 小时会话 |
| `/api/admin/license/session` | DELETE | 注销当前会话 |
| `/api/admin/license/records` | GET | 分页查询授权历史 |
| `/api/admin/license/generate` | POST | 新签或续期，签名并保存加密记录 |
| `/api/admin/license/records/:id/file` | GET | 重新下载该记录的 `license.mrx` |
| `/api/admin/license/backup` | GET | 导出加密记录备份 |

部署时必须在 EdgeOne 服务端环境中配置：

```text
LICENSE_ADMIN_PASSWORD_SCRYPT
LICENSE_PRIVATE_KEY_PEM_B64
LICENSE_SESSION_SECRET_B64
LICENSE_RECORD_ENCRYPTION_KEY_B64
```

这些值只通过 EdgeOne 控制台或受保护的部署配置写入，不写进仓库、构建日志和客户端环境变量。迁移时复用当前本地生成器对应的 Ed25519 私钥，使新后台生成的授权可以被现有桌面端公钥验证。

### 5.3 EdgeOne Blob

每条授权记录保存为独立、不可覆盖的加密对象。对象只暴露版本、记录 ID、创建时间和不可逆机器查询摘要；客户名称、完整机器码、授权码、`license.mrx`、备注和到期时间都放在 AES-256-GCM 密文中。

对象结构确定为：

```json
{
  "version": 1,
  "record_id": "REC-20260726-4F8C2A1D",
  "created_at": 1784995200,
  "machine_lookup": "HMAC-SHA256 的 Base64URL 结果",
  "iv": "12 字节随机 IV 的 Base64URL 结果",
  "auth_tag": "GCM 认证标签的 Base64URL 结果",
  "ciphertext": "授权记录密文的 Base64URL 结果"
}
```

`machine_lookup` 使用记录密钥派生的 HMAC 生成，不直接保存机器码的普通 SHA-256，避免通过常见机器码样本反查。

采用逐记录对象而不是单一可变 JSON 文件，可以避免两次签发同时发生时互相覆盖。历史查询由服务端分页列出对象、解密并筛选；浏览器只接收当前页面需要的数据。

## 6. 授权数据与兼容性

新后台必须复用现有授权协议：

- 产品：`UNIVERSAL_FORMAT_CONVERTER_OFFLINE_PRO`
- 授权封装版本：`ufc-license-v1`
- 激活码前缀：`UFC1-`
- 签名算法：Ed25519
- 默认版本：`pro`
- 默认功能：`basic,convert,export,batch`
- `license.mrx` 内容：当前授权 envelope 的格式化 JSON

签名载荷字段及排列顺序必须与 `tools/admin-license-generator/main.mjs` 和 `apps/desktop/src-tauri/src/license.rs` 保持一致。实现时把共同的纯函数提取为后台可测试模块，不能改变桌面端已使用的规范化方式和字段名称。

每条加密记录的明文内容至少包括：

- `record_id`
- `license_id`
- `parent_license_id`（新签为空，续期指向上一授权）
- `customer_name`
- `machine_id`
- `issued_at`
- `previous_expires_at`
- `expires_at`
- `duration_days` 或 `permanent`
- `edition`
- `features`
- `license_code`
- `license_file_content`
- `remark`
- `created_at`

后台只能显示“已生成”“有效期内”或“已到期”。因为桌面端完全离线，后台不能声称某个授权已经在客户电脑上激活。

## 7. 管理界面

界面以手机优先的单列布局为主，桌面端只增加内容宽度，不增加复杂导航。

### 7.1 登录页

- 一个密码输入框；
- 一个“进入后台”按钮；
- 简单的后台可用状态；
- 不展示部署平台、私钥、环境变量或调试信息。

### 7.2 快速签发

表单字段按以下顺序排列：

1. 客户名称；
2. 大尺寸机器码输入框；
3. 授权时长：30 天、90 天、180 天、1 年、永久；
4. 可选备注；
5. “生成授权”主按钮。

机器码固定为四组四位字符。粘贴时允许带空格、换行或连字符，页面自动去除分隔符、转为大写并重新格式化为 `XXXX-XXXX-XXXX-XXXX`。规范化后的字符必须匹配桌面端实际使用的字母数字表 `[A-HJ-NP-Z2-9]`，不满足时在签名前拒绝。

版本和功能列表保持现有默认值，不在日常表单中展示高级选项，避免误操作。

### 7.3 生成结果

结果卡片首先显示：

- 客户名称；
- 格式化后的机器码；
- 新到期时间；
- “复制授权码”主按钮；
- 授权码二维码；
- “下载 license.mrx”按钮。

完整长授权码默认折叠，需要时可以展开查看。复制成功使用简短状态提示，不弹出阻塞式窗口。二维码只编码已有的完整离线激活码，不创建在线短链接。

### 7.4 授权历史

- 可以按客户名称或机器码搜索；
- 列表默认显示客户、脱敏机器码、签发时间、到期时间和状态；
- 每条记录提供“续期”操作；
- 详情默认折叠，展开后可以重新复制授权码或下载 `license.mrx`；
- 机器码脱敏显示，但查询和续期使用服务端解密后的完整值。

## 8. 数据流

### 8.1 登录

1. 浏览器通过 HTTPS 提交密码。
2. 服务端使用 scrypt 校验 `LICENSE_ADMIN_PASSWORD_SCRYPT`。
3. 成功后签发 8 小时会话 Cookie。
4. Cookie 设置 `HttpOnly`、`Secure`、`SameSite=Strict`，作用路径限制在管理接口 `/api/admin/license`。
5. 后续接口只接受有效会话，并检查同源 `Origin`。

### 8.2 新签

1. 服务端校验会话、机器码、时长和请求大小。
2. 服务端按现有规范创建载荷并使用 Ed25519 私钥签名。
3. 服务端生成激活码和 `license.mrx`。
4. 服务端加密完整记录并写入 Blob。
5. 只有 Blob 写入成功后才把结果返回浏览器。

如果记录保存失败，接口不向管理员返回激活码，避免产生后台查不到的已交付授权。

### 8.3 续期

1. 管理员从历史记录点击“续期”。
2. 服务端按机器查询最新授权记录。
3. 服务端按 `max(当前时间, 最近到期时间)` 计算续期起点。
4. 服务端生成新的 `license_id` 和新签名，旧记录保持不变。
5. 新记录通过 `parent_license_id` 关联上一授权。

客户只需导入最新生成的激活码或 `license.mrx`，桌面端现有逻辑会用新授权覆盖本地旧授权。

### 8.4 备份

备份接口导出 Blob 中的加密 envelope 集合，不导出明文客户资料或私钥。备份文件即使离开 EdgeOne，也必须在持有 `LICENSE_RECORD_ENCRYPTION_KEY_B64` 时才能解密。

## 9. 安全与隐私

- 所有管理接口使用 HTTPS，并返回 `Cache-Control: no-store`。
- 管理页面禁止被搜索引擎索引，并继续使用现有站点的 `frame-ancestors 'none'`、`X-Frame-Options: DENY` 等安全响应头。
- 所有会改变状态的接口校验会话和同源 `Origin`。
- 请求体设置小尺寸上限，拒绝超长机器码、客户名称和备注。
- 服务端日志不记录密码、会话 Cookie、私钥、完整机器码、激活码或授权文件。
- 接口错误不回显内部堆栈、环境变量或 Blob 对象内容。
- 私钥只用于服务端内存中的短暂签名操作。
- Blob 只保存加密记录，不保存用户处理文件。
- 不设置应用层密码复杂度、连续错误锁定或等待规则，这是已经确认的例外。

## 10. 错误处理

| 场景 | 对管理员的表现 |
| --- | --- |
| 密码错误 | 显示“密码不正确” |
| 会话过期 | 返回登录页，未提交内容保留在当前页面内存中 |
| 机器码为空或格式无效 | 在机器码输入框附近提示修正 |
| 私钥或密钥未配置 | 显示“后台暂不可用”，不指出缺少哪个变量 |
| Blob 读取失败 | 历史区域显示“暂时无法读取记录”，不影响退出登录 |
| Blob 写入失败 | 本次签发失败，不返回授权码 |
| 签名失败 | 本次签发失败，服务端记录不含敏感值的错误摘要 |
| 复制或下载失败 | 保留结果卡片，允许管理员重试 |
| 二维码过密或设备无法扫描 | 始终保留复制授权码和下载文件两种方式 |

所有生成操作在提交期间禁用按钮，避免同一页面的重复点击。服务端仍为每次成功请求生成独立记录，不把不同授权静默合并。

## 11. 构建与部署

1. `apps/web` 静态构建继续生成现有官网和分片安装包。
2. EdgeOne 构建脚本把管理页和 Cloud Functions 所需目录包含进部署产物。
3. 先部署无密钥的代码，再在 EdgeOne 控制台配置四个服务端秘密值。
4. 使用现有私钥生成一条测试授权，并用桌面端内置公钥验证。
5. 确认 `gszhmrx.cn` 和 `www.gszhmrx.cn` 的 HTTPS 状态正常后再启用管理入口。
6. 删除或停用 EdgeOne 管理函数即可回滚后台；公开网站和安装包下载不依赖授权后台函数。
7. 回滚期间继续使用：

```text
tools/admin-license-generator/generate-license.cmd
```

旧 CloudBase `licenseAdmin` 保留为历史代码，迁移完成后不再作为生产部署目标。相关运维文档和 npm 脚本需要更新，避免管理员误部署到隔离环境。

## 12. 验证与验收

### 12.1 自动验证

- 现有 Web 测试全部通过。
- 现有隐私边界检查和网络边界检查全部通过。
- 对签名规范、机器码规范化、授权文件格式增加单元测试。
- 使用桌面端对应公钥验证后台生成的 Ed25519 签名。
- 覆盖新签、过期后续期、未到期续期、永久授权和从旧记录点击续期。
- 覆盖密码正确、密码错误、会话过期、无会话访问和退出登录。
- 覆盖 Blob 写入失败时不返回激活码。
- 覆盖加密记录中不出现客户名称、完整机器码和 `UFC1-` 明文。
- EdgeOne 正式构建不包含私钥、密码摘要、记录加密密钥、客户记录或 `.mrx`。

### 12.2 人工验收

- 在国内家庭宽带或移动网络打开 `https://gszhmrx.cn/admin/license/`。
- 使用 6 位纯数字密码成功登录，连续输错不会触发锁定或等待。
- 在手机和电脑上完成新签、复制、二维码展示和 `.mrx` 下载。
- 用真实桌面端导入新生成的激活码和 `license.mrx`，均能激活。
- 对未到期授权续期，确认剩余时间得到保留。
- 刷新页面后历史记录仍存在，可搜索、续期和重新下载。
- 下载加密备份，确认文件不包含可直接阅读的客户或授权数据。
- 官网转换功能和安装包下载继续正常工作。

## 13. 运维边界

- 管理员密码通过更新 scrypt 摘要进行更换，不提供网页内改密码功能。
- 私钥不轮换，除非同步发布包含新公钥的桌面端版本；擅自更换会导致现有桌面端无法验证新授权。
- 记录加密密钥必须单独离线备份；丢失后历史记录无法恢复，但不影响客户已经获得的授权。
- 会话密钥可以更换；更换后所有已登录会话立即失效。
- EdgeOne 免费额度或产品规则可能调整，管理员应在平台通知发生变化时重新评估。日常低频签发和少量加密记录以当前免费额度为目标，不承诺平台永久保持相同配额。

## 14. 成功标准

完成后应同时满足：

- 国内网络可访问同域名私有后台；
- 管理员可以使用简单密码在手机和电脑上签发授权；
- 客户只需处理机器码、复制按钮、二维码或 `license.mrx`；
- 新授权与现有桌面端完全兼容；
- 续期不会损失剩余时间；
- 历史记录可查询、可续期、可重新下载、可导出加密备份；
- 私钥和客户数据不进入公开产物或 Git；
- 后台故障不影响官网、下载和本地转换；
- 本地生成器仍可独立应急。
